# [BUG] AUTH — Access token vẫn dùng được sau khi logout và sau khi đổi mật khẩu

## Thông tin chung
- **ID:** BUG_auth_1795111366_EXP02
- **Severity:** 🟠 Major
- **Priority:** P2
- **Nền tảng:** `api`
- **Môi trường:** Local | `http://localhost:4566/api` (Bun 1.4.5 + Elysia, MySQL 8.4.13) | Windows 11 | —
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)
- **Test case liên quan:** — (exploratory testing `EXP02`, chưa có bộ TC)
- **REQ ID liên quan:** — (chưa có tài liệu requirements)
- **Test data đã dùng:** `admin@example.com` / `123456`; `p1@test.local` / `123456` → `abcdef`
- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. Login `admin@example.com`, giữ `accessToken`.
2. `DELETE /api/logout` → 200.
3. `GET /api/me` với header `Authorization: Bearer <accessToken>` cũ.
4. Tương tự: login `p1@test.local`, `PATCH /api/profile` `{"password":"abcdef","password_old":"123456"}` → 200, rồi gọi `GET /api/me` bằng token cũ.

## Expected Result
Token đã logout, hoặc token phát hành trước khi đổi mật khẩu, phải bị từ chối với 401.

## Actual Result
`GET /api/me` trả 200 kèm thông tin user trong cả hai trường hợp. Token còn hiệu lực tới khi hết hạn (`EXPTOKEN`, local đặt 6 ngày).

## Evidence
```
logout: {"msg":"Logout successfully."} [200]
/me bằng access token đã logout: {"id":"cmwns4oci0000kbc8fjbfy5x4","name":"Admin","email":"admin@example.com",... [200]
```

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** `backend/src/plugins/black-list-token.ts` (`createBlackListToken`) có viết nhưng không nơi nào gọi. Guard `plugins/auth.ts` chỉ `jwt.verify`, không kiểm tra blacklist hay thời điểm đổi mật khẩu.
