# [BUG] AUTH — Refresh token đã bị thu hồi (logout / đổi mật khẩu) vẫn đổi được access token mới

## Thông tin chung
- **ID:** BUG_auth_1795111365_EXP01
- **Severity:** 🔴 Critical
- **Priority:** P1
- **Nền tảng:** `api`
- **Môi trường:** Local | `http://localhost:4566/api` (Bun 1.4.5 + Elysia, MySQL 8.4.13) | Windows 11 | —
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)
- **Test case liên quan:** — (exploratory testing `EXP01`, chưa có bộ TC)
- **REQ ID liên quan:** — (chưa có tài liệu requirements)
- **Test data đã dùng:** `admin@example.com` / `123456`, User-Agent `probe-agent`
- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. `POST /api/login` với `admin@example.com` / `123456` (User-Agent `probe-agent`), lấy cookie `refetchToken` và `accessToken` trả về.
2. `DELETE /api/logout` kèm header `Authorization: Bearer <accessToken>` và cookie `refetchToken`. Kết quả 200 "Logout successfully.".
3. Kiểm tra DB: `UserRefreshToken.revoked` của token này đã chuyển `0 → 1`.
4. `POST /api/refetch-token` với cookie `refetchToken` cũ ở bước 1 (cùng User-Agent).

## Expected Result
Refresh token đã bị thu hồi phải bị từ chối (401/404 "Invalid token."). Sau logout hay đổi mật khẩu thì không cấp được access token mới từ token cũ.

## Actual Result
200 `{"msg":"Refetch token successfully.","accessToken":"eyJ..."}`, vẫn cấp access token mới dù DB ghi `revoked = 1`.

## Evidence
```
revoked trước logout: 0
logout: {"msg":"Logout successfully."} [200]
revoked sau logout: 1
refetch bằng RT đã revoke: {"msg":"Refetch token successfully.","accessToken":"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.e... [200]
```

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** `backend/src/routers/auth-controller.ts` (`/refetch-token`): `prisma.userRefreshToken.findUnique({ where: { tokenHash, expiresAt: { gt }, deviceInfo, ipAddress } })` không có điều kiện `revoked: false`.
