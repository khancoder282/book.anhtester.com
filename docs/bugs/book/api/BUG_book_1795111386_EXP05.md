## Steps to Reproduce
1. `POST /api/book` với `price: -5000` (tên `Sach Gia Am`).
2. `POST /api/book` với `price: 10.5` (tên `Sach Gia Le`).
3. `POST /api/book` với `price: 3000000000` (nhỏ hơn `maximum` 9e12 của schema).

## Expected Result
Từ chối giá âm và giá không phải số nguyên (422 kèm `fields.price`). Giới hạn `maximum` khớp với cột `Int` trong DB.

## Actual Result
Giá âm: 200, lưu `-5000`. Giá 10.5: 200, lưu `10` mà không báo gì. Giá 3 tỷ: 400 "Invalid data." không nói rõ lý do.

## Evidence
```
giá âm            200 {"msg":"Book created successfully."}  -> price -5000
giá thập phân 10.5 200 {"msg":"Book created successfully."}  -> price 10
giá 3 tỷ          400 {"msg":"Invalid data."}
```

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** `bodyBook.price = t.Number({ default: 50_000, maximum: 9_000_000_000_000 })`: không có `minimum`, không phải `t.Integer`, `maximum` lớn hơn `Int` của MySQL (2.147.483.647).
