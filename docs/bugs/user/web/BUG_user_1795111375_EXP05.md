# [BUG] USER — Đang đăng nhập nhưng mở trực tiếp Setting account hoặc My profile thì bị đẩy về trang Sign in

## Thông tin chung
- **ID:** BUG_user_1795111375_EXP05
- **Severity:** 🟡 Minor
- **Priority:** P2
- **Nền tảng:** `web`
- **Môi trường:** Local | Browser pane của Claude Desktop (Chromium) tại `http://localhost:4566` | Windows 11 | 1024×768
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)
- **Test case liên quan:** — (exploratory testing `EXP05`, chưa có bộ TC)
- **REQ ID liên quan:** — (chưa có tài liệu requirements)
- **Test data đã dùng:** `ui1@test.local` / `ui123456`
- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. Đăng nhập `ui1@test.local` tại `/sign-in`, vào được trang chủ.
2. Gõ trực tiếp `http://localhost:4566/user-management/setting-account` vào thanh địa chỉ (hoặc F5 khi đang ở trang đó).
3. Làm lại với `http://localhost:4566/user-management/my-profile`.
4. Đối chứng: mở trực tiếp `http://localhost:4566/book-management`.

## Expected Result
Vẫn ở lại trang đã mở, vì token còn trong `localStorage` và `/api/me` trả 200.

## Actual Result
Bị chuyển sang `/sign-in?redirect=/user-management/setting-account` (2/2 lần) và `/sign-in` (my-profile), dù `/api/me` vẫn trả 200. Riêng `/book-management` không bị. Vào bằng menu avatar → Settings thì được.

## Evidence
```
location sau khi mở setting-account: /sign-in?redirect=/user-management/setting-account
location sau khi mở my-profile:      /sign-in
location sau khi mở book-management: /book-management
localStorage: { hasToken: true }, network: GET /api/me → 200
```

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn (3/3 lần)
- **Workaround (nếu có):** Vào từ menu avatar thay vì gõ URL hoặc F5.
- **Nghi ngờ root cause (nếu phân tích được):** Có thể guard của nhóm route `user-management/*` kiểm tra state user (zustand) trước khi `/api/me` trả về.
