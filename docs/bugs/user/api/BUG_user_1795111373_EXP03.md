# [BUG] USER — User thường khoá được tài khoản và đổi được mật khẩu của user khác

## Thông tin chung
- **ID:** BUG_user_1795111373_EXP03
- **Severity:** 🟠 Major
- **Priority:** P2
- **Nền tảng:** `api`
- **Môi trường:** Local | `http://localhost:4566/api` (Bun 1.4.5 + Elysia, MySQL 8.4.13) | Windows 11 | —
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)
- **Test case liên quan:** — (exploratory testing `EXP03`, chưa có bộ TC)
- **REQ ID liên quan:** — (chưa có tài liệu requirements)
- **Test data đã dùng:** Người thao tác `p3@test.local`; nạn nhân `u1@test.local`
- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. Đăng nhập `p3@test.local` (user bình thường, không phải admin).
2. `PATCH /api/user/<id của u1>` `{"email":"u1@test.local","isActive":false}`.
3. `PATCH /api/user/<id của u1>` `{"email":"u1@test.local","password":"hacked1"}`.
4. `POST /api/login` với `u1@test.local` / `hacked1`.

## Expected Result
Chỉ admin (hoặc chính chủ) mới được khoá tài khoản hay đổi mật khẩu; user thường nhận 403.

## Actual Result
Bước 2 và 3 đều 200 "Updated successfully.". Mật khẩu của u1 bị đổi, tài khoản bị khoá (login trả 403).

## Evidence
```
User thường khoá user khác (isActive=false)  200 {"msg":"Updated successfully."}
User thường đổi mật khẩu user khác           200 {"msg":"Updated successfully."}
login u1 bằng mật khẩu bị đổi                403 {"msg":"User account is disabled."}
```

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** Hệ thống không có khái niệm role. Guard `auth` chỉ xác thực, không phân quyền. Nếu thiết kế cố ý là mọi user đều là admin, PO xác nhận rồi đóng bug.
