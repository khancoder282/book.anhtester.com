# [BUG] USER — API tìm user công khai nhận bộ lọc Prisma tuỳ ý, làm lộ hash mật khẩu và refresh token, dẫn tới chiếm được tài khoản

## Thông tin chung

- **Severity:** 🔴 Critical
- **Priority:** P1
- **Nền tảng:** `api`
- **Môi trường:** Local | `http://localhost:4566/api` (Bun 1.4.5 + Elysia, MySQL 8.4.13) | Windows 11 | —
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)

- **REQ ID liên quan:** — (chưa có tài liệu requirements)
- **Test data đã dùng:** Tài khoản bị chiếm: `admin@example.com` (refresh token phát hành với User-Agent `probe-agent`)
- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. **Không đăng nhập**, gọi `GET /api/user?search={"password":{"startsWith":"$argon2"}}`. User có hash khớp được trả về; đổi tiền tố thành `zzz` thì danh sách rỗng.
2. Gọi `GET /api/user?search={"refreshTokens":{"some":{"deviceInfo":{"contains":"probe-agent"},"tokenHash":{"startsWith":"<tiền tố>"}}}}`, thêm dần từng ký tự để dò ra trọn `tokenHash`.
3. Gửi `POST /api/refetch-token` với cookie `refetchToken=<tokenHash vừa dò được>` và cùng User-Agent.
4. Dùng access token nhận được để gọi `GET /api/me`.

## Expected Result
`search` chỉ là chuỗi tìm kiếm trên các cột cho phép (name, email, phone, address). Không lọc được theo `password` hay quan hệ `refreshTokens`.

## Actual Result
Lọc được theo mọi cột và quan hệ. PoC trên local dò ra trọn refresh token của admin sau **1623 request không cần đăng nhập**, đổi được access token và `/me` trả đúng tài khoản `admin@example.com`. Giá trị dò được viết toàn chữ thường vẫn dùng được, vì MySQL so sánh `*_ci` không phân biệt hoa thường. Ngoài ra, khi `search` sai cú pháp thì response lộ cả đường dẫn file mã nguồn và dòng code.

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** `backend/src/plugins/filterTable.ts`: nếu `search` là JSON thì `JSON.parse(search)` được dùng **nguyên văn** làm `where`. `GET /api/user` không có guard `auth`. Cookie refresh chính là `tokenHash` lưu trong DB, nên việc hash token không có tác dụng gì. `/api/book` và `/api/promotion-book` dùng chung `filterTable`. Có thể chiếm được tài khoản là nhờ kết hợp với BUG_auth_1795111365_EXP01.
