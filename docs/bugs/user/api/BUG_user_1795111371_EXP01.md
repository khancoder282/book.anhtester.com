# [BUG] USER — Sửa profile hoặc user mà không gửi email thì email bị ghi đè thành user@example.com

## Thông tin chung
- **ID:** BUG_user_1795111371_EXP01
- **Severity:** 🔴 Critical
- **Priority:** P1
- **Nền tảng:** `api`. Cũng tái hiện trên: web: trang **Setting account** gửi `PATCH /api/profile` chỉ có `{ config }`, nên chỉ cần bấm **Save** là email bị đổi (đã tái hiện bằng `ui1@test.local`).
- **Môi trường:** Local | `http://localhost:4566/api` (Bun 1.4.5 + Elysia, MySQL 8.4.13) | Windows 11 | —
- **Build / Version:** `deploy-vps` @ `5fcd241` (code backend từ `64d41c0`, frontend build từ cùng commit)

- **REQ ID liên quan:** — (chưa có tài liệu requirements)

- **Ngày phát hiện:** 20-11-2026

## Steps to Reproduce
1. Đăng ký và đăng nhập `p1@test.local` (DB chưa có ai dùng email `user@example.com`).
2. `PATCH /api/profile` với body `{"name":""}` (hoặc chỉ `{"phone":"0901234567"}`, không có `email`). Kết quả 200 "Updated profile successfully.".
3. `POST /api/login` lại bằng `p1@test.local` với mật khẩu đúng.
4. Với một user khác (`p3@test.local`), gọi `PATCH /api/profile` `{"phone":"0901234567"}`.
5. Trên UI: đăng nhập `ui1@test.local`, vào menu avatar → **Settings**, bấm **Save** (không đổi gì).

## Expected Result
Chỉ những trường được gửi mới bị cập nhật; email giữ nguyên.

## Actual Result
Bước 2: email của `p1` bị đổi thành `user@example.com`, bước 3 trả 404 "Email not found" nên user mất quyền đăng nhập bằng email của mình. Bước 4: từ lúc đó **mọi user khác** sửa profile mà không gửi email đều thất bại (422 thông báo vô nghĩa, xem BUG_auth_1795111368_EXP04) và dữ liệu không được lưu. `PATCH /api/user/{id}` bị y hệt (trả "Email already exists."). Bước 5: DB ghi `email = user@example.com` cho UI Tester, và sau đó login bằng `ui1@test.local` trả 404.

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn
- **Workaround (nếu có):** Không có
- **Nghi ngờ root cause (nếu phân tích được):** Commit `64d41c0` thêm `default: "user@example.com"` cho `email` trong schema `t.Partial(...)` của `PATCH /profile` (`auth-controller.ts`) và `PATCH /user/:id` (`user-controller.ts`). Elysia điền giá trị mặc định khi client không gửi email, rồi handler ghi thẳng `email: body.email` vào DB. Nên bỏ `default` khỏi schema của PATCH, hoặc chỉ cập nhật email khi client thật sự gửi.
